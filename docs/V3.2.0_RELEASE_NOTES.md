# OneKit JS V3.2.0 Release Candidate

**Framework package:** `onekit-js@3.2.0`  
**Starter package:** `create-onekit@1.0.10`  
**Branch:** `V3`

## Release decision

`onekit-js` moves from `3.1.19` to **`3.2.0`** because this candidate groups additive V3 framework capabilities across ISR, streaming SSR, edge deployment, generated route declarations, and official provider integrations. These additions are documented as Experimental where their deployment or provider semantics remain application-owned.

`create-onekit` moves from the currently published **`1.0.9`** to **`1.0.10`**. The creator package does not introduce a new project architecture in this increment; the patch release synchronizes its package metadata, smoke-install documentation, and release instructions while retaining the compatible dependency range `onekit-js@^3.1.19`.

| Package | Previous published version | Candidate version | Release type | Dependency policy |
|---|---:|---:|---|---|
| `onekit-js` | `3.1.19` | `3.2.0` | Minor | Additive APIs; existing stable contracts remain compatible. |
| `create-onekit` | `1.0.9` | `1.0.10` | Patch | Keeps `onekit-js@^3.1.19`, which accepts the 3.2.x line. |
| `@onekit-js/redis` | Not published | `0.1.0` | Initial experimental package | Optional `redis` and `onekit-js` peer dependencies. |
| `@onekit-js/deno-kv` | Not published | `0.1.0` | Initial experimental package | Deno KV runtime contract and `onekit-js` peer dependency. |
| `@onekit-js/vercel-global-config` | Not published | `0.1.0` | Initial experimental package | Optional `@vercel/global-config` and `onekit-js` peer dependencies. |

## Included work

The framework candidate includes serialized ISR cache contracts, cache leases, stale-refresh scheduling, structured lifecycle events, bounded streaming boundary concurrency, Fetch-native edge scheduling, generated route declarations, and the initial official Redis, Deno KV, and Vercel Global Config integrations. The provider packages are maintained separately so core applications do not receive vendor SDKs transitively.

The Vercel package follows the current platform name **Global Config**. Vercel documents Edge Config as renamed to Global Config and identifies `@vercel/global-config` as the current SDK.[1] Global Config is a read-optimized configuration store; the OneKit package therefore exposes a read-only configuration reader and does not claim to be an ISR cache or regeneration lock.

## Upgrade and publish order

Publish the framework package first, then publish the creator package, because the creator smoke-install should be able to resolve the new framework release. The automated workflows publish only matching tags:

```bash
# From the repository root, after validation and review
npm publish --access public --provenance

# From create-onekit/, after onekit-js@3.2.0 is available
npm publish --access public --provenance
```

The preferred GitHub Actions path is:

```bash
git push origin V3
git tag v3.2.0
git push origin v3.2.0
# wait for onekit-js publication and registry verification
git tag create-onekit-v1.0.10
git push origin create-onekit-v1.0.10
```

Publishing is intentionally not represented as complete until npm registry metadata, tarball contents, clean installation, CLI help, ESM/CJS imports, and the generated starter workflow are verified.

## Remaining boundaries

This release does not provide React Flight/RSC compatibility, vendor deployment manifests, automatic platform environment typing, CDN cache-control policy, authenticated on-demand revalidation, OpenTelemetry exporters, or a universal database/Redis runtime. Redis and Deno KV lease expiry correctness depends on the provider and deployment configuration; provider outage, retry, timeout, connection, eviction, and observability policies remain application-owned.
